# Miru リファクタリング計画

対象は [#32 のレビュー済みブラウザー版](https://github.com/koumatsumoto/miru/pull/32)。外観・操作・入出力はそのままに、変更理由が違うコードを分ける。行数の削減や新しい抽象化自体は目的にしない。画面の基準は [デザインシステム](design-system.md) を使う。

## 今回の整理

| 領域         | 現状と整理方針                                                                                                                                                                                  |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Web          | `main.ts` に起動、タブ、プレビュー、設定と検索のイベントが集まっている。HOME 検索を独立させ、遅い応答の破棄・IME・フォーカス制御をそちらに置く。フォルダ内絞り込みやタブの状態は混ぜない。      |
| デザイン     | 色は `src/shared/theme.ts`、シェルの寸法・文字・動きはデザイントークン、個別の配置は各部品の CSS を正本とする。共通のアイコンボタンを一か所に寄せるが、歯車の高さなど意図の違う寸法は維持する。 |
| サーバー     | HTTP の受け付けと認証・境界検査から、認証後のファイル/Git/設定操作を分ける。新しい公開 API、キャッシュ、ルーターは足さない。                                                                    |
| CLI          | 引数を意味のある操作に変える処理と、プロセス・ブラウザー・更新の副作用を分ける。明示指定されたパスをコマンドと取り違えない。                                                                    |
| テスト・配布 | テスト用ワークスペース生成を Chromium の操作手順から分ける。テスト対象・実行手順・観測は削らない。CLI の同梱先、オフライン資産、ライセンスを維持する。                                          |

## 守る契約と今回変更しない場所

- `miru` と `ev`、`dist/cli.mjs`、更新判定に使う `src/cli.ts`・`scripts/build.mjs`・`vite.config.ts`、`MIRU_BUILD_DIR` を維持。常駐プロセスのプロトコルと更新のロールバックは変更しない。
- ローカルに限定したリスナー、Host／Origin／セッションの確認、ファイル範囲・入力サイズ・同時操作の制限を維持。プレビュー隔離・CSP・外部通信の扱いを変えない。
- タブごとの選択、既定のフィルター、連続入力の順序、テーマ設定ファイルを維持。ライト／ダーク、キーボード操作、動きを減らす設定も受け入れ条件にする。
- `native/` は独立した WinUI 実験として確認したが、ブラウザー版へ統合せず変更しない。Git の差分算法、プレビュー処理、更新の状態遷移も、具体的な不具合や改善根拠が出たときに個別に扱う。

## 受け入れ基準

1. 差分は責務の移動と重複の削減に限定する。CLI の引数解釈と認証後の操作に単体テストを置き、検索の遅延応答を Chromium で確認する。既存の HTTP・Git・プレビューの境界テストは残す。
2. Node 24／26 の型・lint・整形・単体・ビルド、依存の監査、パッケージと常駐更新のスモーク、Chromium、Windows Explorer の非 GUI スモークを通す。
3. Chromium でライト／ダーク、既存の検索・絞り込み、同一ポートの独立したタブ、プレビューからの外部通信ゼロ、Git index の不変を確認する。実機 WSL／Windows の操作は CI の成功と区別する。
