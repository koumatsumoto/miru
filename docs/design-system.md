# Miru デザインシステム

## 原則と文言

- 主役はファイルとその中身。ヘッダーは HOME 検索、左はフォルダと絞り込み、右はプレビュー・コード・差分または設定、下は状態とビルド情報に絞る。ファイル未選択時の右ペインは空のままにする。
- 操作名は短く、対象と結果を区別する。「親を一段表示」は階層を移動、「ここをトップにして表示」は表示範囲を切り替え、「最新に同期」はローカルを読み直す。サーバーや Git の同期とは呼ばない。長い説明は通常時に並べず、操作できない理由や次にできることがあるときに出す。
- ヘッダーの「ファイルを検索」は HOME が範囲。左の「このフォルダ内を絞り込み」は現在のフォルダ以下のファイル名・相対パスが範囲。どちらも本文検索ではない。

## 色とテーマ

色は GitHub 系のライト／ダークを対で扱う。色値の正本は [`src/shared/theme.ts`](../src/shared/theme.ts)。用途が同じシェルの値は [`design-tokens.css`](../src/web/design-tokens.css) に置き、ツリーの選択のような部品固有の合成色はその部品に留める。

| 役割             | トークン                                 | 使いどころ                                                                                                     |
| ---------------- | ---------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 主面・副面       | `--bg` / `--canvas`                      | プレビュー・メニュー・ヘッダーを主面、Explorer・フッター・検索入力を副面。面の色を任意の白・黒で上書きしない。 |
| 本文・補助・境界 | `--fg` / `--muted` / `--border`          | ファイル名、補助パス・バージョン、細い区切り。補助色を本文の代わりにしない。                                   |
| 操作・選択       | `--accent` / `--onAccent` / `--selected` | 青はフォーカス、操作や選択の手掛かり。ツリーのホバー・非アクティブ選択・アクティブ選択は別々の背景役割にする。 |
| Git              | `--changed` / `--added` / `--removed`    | ツリーの変更マークは黄系、差分の追加・削除行は緑系・赤系。削除ファイルは取り消し線も使う。                     |

共通の `--border` は面を区切るための淡い罫線。新しい操作部品を識別する唯一の手掛かりにはせず、ラベル・記号・明瞭なフォーカス表示を組み合わせる。

未設定ならブラウザーの配色設定を初期値にする。選択済みの「ライト」「ダーク」は `~/.miru/settings.json` に保存し、シェル・プレビュー・コード・差分を同じテーマで描く。ネイティブ入力も `color-scheme` で合わせる。

## 階層・余白・アイコン

- ヘッダーは最小 56 px。左にロゴ、中央に HOME 検索（120〜400 px の可変幅）。余った幅を別の操作で埋めない。
- Explorer はデスクトップで初期 300 px、最小 200 px。フッター左セルの右罫線は Explorer の境界と揃える。画面幅 700 px 以下では Explorer を 210 px に固定し、リサイズ用の取っ手を隠す。
- Explorer は横余白 12 px、見出しは追加で 4 px 内側。フォルダ名 15 px、補助パス 11 px。ツリーは日本語のシステム書体を優先し、13 px / 20 px、行高 24 px。階層は 13 px ずつ下げ、深くなってもファイル名の幅を残す。長い行名は省略記号、見出しの長いパスは折り返す。
- 右ペインはファイル・設定で同じ見出し構造（最小 64 px、デスクトップ横余白 24 px）。コンテキストメニューと絞り込みは角丸・枠・薄い影で面を持ち上げ、行の最小高は 32 px。絞り込みは 12 px、コンテキストメニューは 13 px。フッターは最小 29 px、状態文は 11 px、右端のバージョンは 10 px の等幅数字。
- ツールバーは「↑」と絞り込みの 16 px 線画を 28 px 四方の中央に、左下の歯車は 18 px の線画を 28 × 26 px の操作域に置き、左余白 10 px を保つ。共通の線幅・端の丸み・`currentColor` を使う。ツリーは 12 px のシェブロンと 16 px のファイル種別アイコンを分け、フォルダだけ塗りを薄く入れる。SVG 自体は装飾扱いにして、ボタンには読める名前を付ける。

## 状態とアクセシビリティ

- ホバーは薄い塗り。選択行はフォーカスがツリーの外に出ても分かるようにし、内側では青系で強調する。キーボードのフォーカス枠を消さない。階層ガイドは行の塗りより上に保つが、クリックを妨げない。
- 展開はシェブロンの向きと `aria-expanded`、変更は点と読み上げラベル、削除は取り消し線も使う。絞り込み中はアイコンの点と説明で伝える。既定の「.git を除外」だけでは絞り込み中の強調を付けない。
- メニューは右クリックまたは Shift+F10／メニューキーで開け、矢印・Home・End で移動し、Escape で元の操作に戻る。絞り込みを開いたら入力欄に移動し、Escape でトグルに戻す。リサイズは左右矢印・Home・End でも操作できる。スキップリンクを残す。
- 動きを減らす設定ではアニメーションを使わない。通常時もポップオーバーの出現は 120 ms、仕切りのハイライトは 160 ms 程度で、操作は完了を待たせない。強制カラーでは `Highlight` と `GrayText` を使い、フォーカス・ガイド・仕切りを影や半透明の色だけに頼らせない。

## 実装上の正本

[`styles.css`](../src/web/styles.css) は読み込み順だけを持つ。新しい画面でもまず既存の役割を再利用し、意味の違う寸法まで無理に同じトークンにしない。

| 場所                                                | 責務                                                                                               |
| --------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| [`design-tokens.css`](../src/web/design-tokens.css) | 書体、文字サイズ、共通の余白・角丸、アイコンの線幅、短い動き                                       |
| [`base.css`](../src/web/base.css)                   | 控えめな初期化、標準入力・フォーカス、`.line-icon` と `.popover-surface`（位置・影・動きは部品側） |
| [`shell.css`](../src/web/shell.css)                 | ヘッダー、HOME 検索、サイドバーとフッターで共有する列、仕切り                                      |
| [`explorer.css`](../src/web/explorer.css)           | 左のツリーとフォルダ内絞り込み、コンテキストメニュー                                               |
| [`viewer.css`](../src/web/viewer.css)               | ファイルと設定の共通見出し、各プレビュー、コードと差分                                             |

## アプリ本体とプレビューの境界

シェルのレイアウト・部品スタイルと、文書内の [`document.css`](../src/web/document.css) は分ける。Markdown／HTML の隔離フレームに共有するのはテーマの色変数と文書用スタイルのみ。閲覧ファイルの CSS・スクリプト・ナビゲーションをシェルには持ち込まない。文書の安全制約を見た目のために緩めず、コードハイライト・Mermaid・PDF も既存の描画経路を使う。

## 変更時の確認

- `npm run check` と `npm run test:browser`（先にビルド）。ライト／ダーク、幅の狭い画面、Explorer をリサイズした状態で、検索幅・ヘッダーの位置・フッターの境界・長い日本語名を確認する。
- キーボードだけで検索・絞り込み・右クリックメニュー相当・設定・区切りの操作を試す。ホバー／選択／フォーカスの違い、操作後に戻るフォーカス、動きを減らす設定と強制カラーでの見え方を確認する。
- ファイル未選択、通常と「変更ファイルのみ」、削除・検索結果なし・Git 状態が使えない場合を確認する。文書 CSS を触ったら、両テーマで Markdown／HTML・コード・差分を表示し、閲覧内容がアプリの操作や外部通信を引き起こさない既存テストも通す。
